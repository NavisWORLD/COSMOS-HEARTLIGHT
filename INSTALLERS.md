# COSMOS HEARTLIGHT — Installers & Native Apps

Version: **0.3.0 — Install Everywhere**

## Release checklist

- ✅ One-click Windows `.exe` installer
- ✅ macOS `.app` bundle and `.dmg` installer image
- ✅ polished Android application (`.apk`)
- ✅ polished native iPhone/iPad application project and packaged iOS builds
- ✅ packaged GitHub Release with binaries and SHA-256 checksums

## Windows

Download `COSMOS-HEARTLIGHT-Setup.exe` from the GitHub Release and run it. The installer deploys a self-contained .NET launcher and the local HEARTLIGHT application. HEARTLIGHT opens in the default browser from a localhost-only server; no cloud account or remote backend is required.

The installed launcher also provides a tray menu for reopening HEARTLIGHT or closing the local server.

## macOS

Download `COSMOS-HEARTLIGHT-macOS.dmg`, open it, and copy `Heartlight.app` to Applications. A zipped `.app` is also included.

The public CI build is ad-hoc signed, not Apple-notarized. macOS may require the user to approve the app in Privacy & Security. Production notarization requires an Apple Developer signing identity and notarization credentials.

## Android

Download `COSMOS-HEARTLIGHT-Android.apk` and install it on Android 7.0+ after allowing installation from the chosen file source. The app embeds HEARTLIGHT locally and uses Android's secure `appassets` origin. Camera permission is requested only for the optional ambient color/brightness sensor.

The public APK is a development/release-distribution build, not a Google Play Store submission. Play Store publishing requires a persistent Play signing key and store account.

## iPhone / iPad

HEARTLIGHT now includes a native SwiftUI iOS/iPadOS application with Child, Teacher, Ambient Sensor, and Privacy/About sections.

The release contains:

- `COSMOS-HEARTLIGHT-iOS-Simulator.app.zip` — directly usable in the iOS Simulator.
- `COSMOS-HEARTLIGHT-iOS-unsigned.ipa` — an unsigned device package for downstream signing/re-signing.

A normal physical iPhone requires an Apple-issued signing identity/provisioning profile. App Store/TestFlight distribution requires an Apple Developer account. The project source in `native/apple_app/` is ready for that signing step.

The existing installable PWA remains available on physical iPhone/iPad through Safari → Share → Add to Home Screen without App Store signing.

## Native libraries

The release also publishes:

- `heartlight-cpp-linux.zip`
- `heartlight-rust-linux.zip`

These contain the C++/C ABI and Rust/FFI build outputs for integration into other applications.

## Verification

Every packaged release is generated by `.github/workflows/release-installers.yml`. The release job generates `SHA256SUMS.txt` for the published assets.

HEARTLIGHT remains an educational/accessibility support system, not a medical device, diagnosis engine, automated discipline system, or substitute for qualified educational/clinical judgment.
