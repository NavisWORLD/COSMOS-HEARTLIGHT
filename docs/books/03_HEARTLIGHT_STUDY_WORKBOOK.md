# HEARTLIGHT — Study Workbook

Use this workbook for staff learning, student-support teams, demos, or portfolio presentations. Do not use real student identifying information in public exercises.

## Exercise 1 — Observation versus interpretation

Rewrite five subjective statements into observable descriptions.

Example: `He was being difficult` -> `He pushed the worksheet away, covered his ears, and did not begin after three verbal prompts.`

## Exercise 2 — Communication channels

List at least six ways a learner could communicate "I need a break" without speaking those words.

## Exercise 3 — Sensory map

Walk through a classroom and note controllable sources of sound, glare, visual clutter, movement demand, proximity, and transition uncertainty.

## Exercise 4 — Support menu

Choose one classroom scenario and generate three support options. Rank them by learner preference and least restriction, not adult convenience.

## Exercise 5 — 12D state

Create a synthetic state vector and explain what each value means. Then name three conclusions the state does **not** justify.

## Exercise 6 — C++ demo

Build the C++ example and change one dimension at a time. Record which transparent rule changes the suggestion set.

## Exercise 7 — Rust demo

Run the Rust example and compare the support IDs with the C++ engine for an equivalent synthetic scenario.

## Exercise 8 — Privacy review

Identify every point where data could persist. Mark each as ephemeral, explicitly stored, exported, or external. Remove anything that is not necessary.

## Exercise 9 — Product demonstration

Give a five-minute demo for three audiences: teacher, school administrator, and software engineer. Notice how the same product requires different explanations.

## Exercise 10 — Validation plan

Design a pilot that measures usability, accessibility, teacher burden, learner preference, and whether suggested supports are actually useful. Do not claim clinical efficacy without appropriate study design and review.
